# 00-governance — Project Rules

This section defines the working agreements and documentation rules for the Simple Stock Flow project.

These rules guide how project documentation is written, reviewed, maintained, and delivered. Any rule that is not defined by the data model is treated as a project agreement or assumption.

## Documents in This Section

| File | Purpose |
|------|---------|
| `git-conventions.md` | Branch naming, commit messages, and collaboration rules |
| `agile-conventions.md` | Planning, task tracking, and team coordination |
| `definition-of-done.md` | Criteria for considering a task complete |
| `definition-of-ready.md` | Criteria for accepting a task before work begins |
| `documentation-rules.md` | Documentation structure, language, and maintenance |
| `microservices-documentation.md` | Guidance for documenting services or components, when applicable |
| `security-policy.md` | General security principles for the application |
| `security-rules.md` | Technical rules for handling input, credentials, and data safely |

## How Governance Applies

These rules apply to the project documentation and development workflow.

- Project requirements and business rules must remain consistent with `spec/data-model.md`.
- Claims derived from the data model must reference the relevant section or constraint.
- Decisions not established by the data model must be identified as assumptions or project agreements.
- Documentation must be updated when an approved change affects it.
- Rules must reflect the actual scope and architecture of Simple Stock Flow, rather than unrelated project-specific practices.

## Maintaining Governance

Changes to these rules should be documented and agreed upon by the project team.

Governance documents must remain consistent with the project scope, requirements, domain model, and architecture.
