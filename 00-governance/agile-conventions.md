# Agile Conventions

## Purpose

This document describes a simple approach to organizing work for Simple Stock Flow.

The practices below are proposed project agreements. They do not imply that the project already uses a specific Agile tool, sprint schedule, or estimation system.

## Work Organization

Tasks should be divided into small, understandable items.

Each task should identify:

- The objective.
- The expected result.
- The documents or components affected.
- Any relevant dependencies.
- The criteria used to verify completion.

## Prioritization

Work should be prioritized according to:

1. Requirements and instructions provided by the instructor.
2. Consistency with the data model.
3. Dependencies between documents or features.
4. Corrections needed to remove contradictions.
5. Improvements that do not change the agreed scope.

## Planning and Tracking

The team may use a task list, issue tracker, or repository checklist to track progress.

The selected tool should be documented if the team formally adopts one. No external tracking platform is assumed by this document.

## Communication

When several people contribute, changes that affect shared requirements or design decisions should be communicated to the team.

Questions about unclear requirements should be recorded instead of resolved through unsupported assumptions.

## Documentation Changes

Documentation should be updated when an approved change affects the scope, requirements, domain rules, or architecture.

Related documents should be reviewed together to avoid contradictory information.

## Completion

A task is considered complete when it meets the applicable criteria in `definition-of-done.md`.

For documentation tasks, the content must also follow `documentation-rules.md`.
